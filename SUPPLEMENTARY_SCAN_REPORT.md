## §A — Database & multi-tenant (schema.prisma + 33 SQL files + orgOwnership.ts)

### A1 (HIGH) — DB-layer RLS is non-functional; tenant isolation is 100% application-layer
`rls_policies_all_tables.sql` + live DB role config + `server/src/config/database.ts:128`.
RLS is defeated **three ways simultaneously** on the app's data path:
- The app connects via `pg.Pool` as the `postgres` role, which has **`rolbypassrls = true`**.
- **0 / 324** tables have `FORCE ROW LEVEL SECURITY`, so even a table owner bypasses policies.
- The policy predicate `get_current_organization_id()` reads `current_setting('request.jwt.claims')`,
  a variable only Supabase PostgREST/GoTrue sets. The Express/Prisma backend **never** calls
  `set_config`/`SET LOCAL` (0 hits in `server/src`). With RLS forced, the predicate would return NULL
  and every query would read **zero rows** — proving the current "working" state depends on the bypass.

**Impact:** no defense-in-depth. A single missing `where: { organizationId }` in any of ~200 org-scoped
models is a direct cross-tenant breach with nothing behind it to catch it.
**Fix:** connect as a dedicated non-owner role *without* `BYPASSRLS`; `ALTER TABLE … ENABLE + FORCE ROW
LEVEL SECURITY` on every tenant table; inject org context per request via a Prisma `$extends` that runs
`SELECT set_config('app.current_org', $org, true)` at transaction start; rewrite policies to read that GUC.

### A2 (HIGH) — The repo's canonical RLS migration is inert / non-reproducible
`rls_policies_all_tables.sql` contains **512 `CREATE POLICY`** but **0 `ENABLE ROW LEVEL SECURITY`** and
**0 `FORCE`** statements (CREATE POLICY without ENABLE does nothing), and references
`public.get_current_organization_id()` **512×** while defining it in **no** repo SQL file (it exists only
in the live DB + 2 markdown docs). Re-running this file on a fresh DB would *not* reproduce the live
posture. **Fix:** add the function `CREATE` and the `ENABLE/FORCE` statements into the migration.

### A3 (MED) — Competing, stale schema definitions coexist in the live DB
`supabase_schema.sql` / `database_schema.sql` define **snake_case** `organizations`/`users` with an open
`USING(true)` RLS scheme, while Prisma owns **PascalCase** models. The live DB contains **both** families
simultaneously. Root-level `MISSING_TABLES_SQL.sql`, `add_missing_tables.sql`, `fix_database_schema.sql`,
`migrations/new_pages_tables.sql`, `migrations/prisma_schema_additions.prisma` overlap/conflict with Prisma
and are not run by `prisma migrate`. **Fix:** make `prisma/migrations` the single source of truth; archive
the duplicates; drop the orphaned snake_case tables after confirming they hold no live data.

### A4 (MED) — Application connects as a `BYPASSRLS` superuser-equivalent role
`server/src/config/database.ts`. Beyond RLS, any `$queryRaw`/injection flaw runs with full bypass.
**Fix:** least-privilege application role.

### ✓ Confirmed sound
- **`server/src/utils/orgOwnership.ts` is correct** and not bypassable in the audited ways
  (id AND org predicate; null→404; unknown model→500; parent-path form used correctly by controllers).
  Two LOW cautions: it does not guard against an **empty `orgWhere`** (a future caller passing `{}` would
  silently lose org scoping); and it trusts `req.user!.organizationId` (relies on middleware ordering).
- The 81 models without `organizationId` are all legitimate child entities (parent FK + `onDelete: Cascade`)
  or intentional global/system tables — **no model-layer cross-tenant leak**, *provided controllers verify
  the parent chain* (which is the app-layer dependency A1 makes load-bearing).

## §B — SSRF / CodeQL reconciliation (patValidationService.ts + workflows/codeql.yml)

### B1 (HIGH) — patValidationService SSRF is NOT fixed (open CodeQL criticals)
Remediation log row 399 marks this `FIXED`, but current code disagrees. **12 validators interpolate a
user-controlled `baseUrl` into the outbound URL with no `assertSafeOutbound` guard at all** (only the
bypassable boolean `isUrlSafe`, or nothing): Sentry (`:959`), Auth0 (`:1028`), Datadog (`:1064`), Qualys
(`:1105`), Tenable (`:1152`), CrowdStrike (`:1195`,`:1210`), Palo Alto (`:1248`), Rapid7 (`:1288`), ADP
(`:1413`), Salesforce (`:1684`,`:1708`) — each an **open CodeQL critical** (`js/request-forgery`).
Even the ~9 *guarded* validators remain flagged and exploitable because axios is **not** routed through
`safeFetch`, so there is **no redirect re-validation and no DNS-rebinding guard** on the actual request.
**Fix:** route every outbound validation request through `safeFetch` (re-validates redirects + resolved IP)
on the final resolved URL; add `assertSafeOutbound` to the 12 unguarded validators as a minimum stopgap.

### B2 (HIGH) — CodeQL backlog is an order of magnitude larger than reported
Live `gh api code-scanning/alerts` (current, 2026-06-02): **1,163 open alerts — 24 critical, 199 high,
292 medium, 607 note** — vs the report's parked "~2 critical + ~66 high." 23 open `js/request-forgery`
(22 in patValidationService, plus `routes/sso.ts:184`, `regulatoryIntelligenceFabricService.ts:118`).
**Fix:** triage the 24 critical + 199 high; this is a real security-review backlog, not a footnote.

### B3 (MED) — CodeQL is defined twice with different query suites and gates nothing
`ci.yml:408-420` (`security-and-quality`) duplicates standalone `codeql.yml` (default suite); neither fails
the build on findings, so nothing blocks a merge despite the backlog. **Fix:** consolidate to one config;
enable "Require code scanning results" in branch protection.

## §C — ZK trusted setup (server/scripts/trusted-setup.sh, server/src/zkp/setup-circuits.sh)

### C1 (HIGH) — Hardcoded ceremony entropy breaks ZK soundness
`server/scripts/trusted-setup.sh:60,70` derives Groth16 toxic waste from the **literal strings**
`"random text"` / `"another random text"`. Anyone with the repo knows the entropy → proofs for all
circuits can be **forged**. **Fix:** source `-e` from `/dev/urandom` and/or a real multi-party ceremony.

### C2 (HIGH) — Predictable (timestamp) ceremony entropy
`server/src/zkp/setup-circuits.sh:181` uses `-e="$(date +%s)"`. A guessable timestamp is low-entropy;
an attacker who knows the approximate setup time reconstructs the toxic waste for `compliance_check`,
`credential_verification`, `data_ownership`. **Fix:** `-e="$(head -c 64 /dev/urandom | base64)"`.
*(Also MED: the powers-of-tau block is regenerated inside the per-circuit loop, reusing the same
predictable randomness across circuits.)*

## §D — CI/CD supply chain (.github/workflows/*, dependabot.yml)

### D1 (HIGH) — No least-privilege `permissions:`; `GITHUB_TOKEN` is write-all
`ci.yml` and `mobile.yml` set no top-level `permissions:`; ~14 of ~18 jobs inherit the legacy
**read/write-all** token. **Fix:** top-level `permissions: contents: read`, grant the minimum per job.

### D2 (HIGH) — No third-party action pinned to a commit SHA
Every external action uses a mutable tag (`gitleaks/gitleaks-action@v3`, `8398a7/action-slack@v3`,
`aquasecurity/trivy-action@v0.36.0`, `expo/expo-github-action@v8`, …). A compromised tag = pipeline RCE
with the write-all token from D1. **Fix:** pin to `@<sha>  # vX.Y.Z`.

### D3 (HIGH/MED) — `npm audit fix --force` runs unattended
`dependency-scan.yml:80-84` runs `npm audit fix --force 2>/dev/null || true` (pulls breaking majors,
output swallowed, result discarded). **Fix:** remove, or have it open a reviewed PR.

### D4 (MED) — Audit gate only fails on `critical`; server audit `continue-on-error: true`
`ci.yml:357-367` — HIGH advisories never fail CI. **Fix:** gate at `--audit-level=high` with a documented
allowlist for the known-unfixable server set.

### ✓ Positives: no `pull_request_target`, no `${{ github.event.* }}` → `run:` injection, no echoed
secrets; Node 22 consistent across CI/Dockerfile/`engines`. Cosign signing, Trivy, GitLeaks, manual prod
approval, pre-migration backups all present.

## §E — Containers & edge (Dockerfile×2, docker-compose×6, nginx, logstash)

### E1 (HIGH) — Elasticsearch HTTP + transport ports published to host
`docker-compose.elk.yml:10-11` (`9200:9200`, `9300:9300`). 9300 inter-node transport must never be host-
exposed. **Fix:** drop the `ports:` block (peers reach ES on the internal network) or bind to loopback.

### E2 (MED→HIGH) — Prod nginx mounts a non-existent config dir → no TLS/server block
`docker-compose.prod.yml:104` mounts `./nginx/conf.d` (which does not exist); `nginx.conf:49` includes
`/etc/nginx/conf.d/*.conf`, so prod nginx starts with **no server block, no TLS, no proxy**. The real
`nginx/default.conf` is never mounted in prod. **Fix:** mount the file directly:
`./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro`.

### E3 (MED) — Datastore/admin ports exposed on host
`docker-compose.yml` Postgres/Redis; `docker-compose.security.yml` Prometheus(no auth, `--web.enable-
lifecycle`)/Alertmanager(no auth)/Grafana. **Fix:** bind to `127.0.0.1` or put behind the authed proxy.

### E4 (MED) — Falco `privileged: true` + docker-socket mount; OPA Dockerfile broken HEALTHCHECK
`docker-compose.security.yml:12` / `falco.docker-compose.yml`; `server/docker/opa/Dockerfile:10` uses
`wget` on a distroless image with no `wget` → container perpetually unhealthy. **Fix:** minimal caps for
Falco; correct OPA healthcheck.

### E5 (MED) — Logstash HTTP ingest unauthenticated and host-published
`logstash.conf` + `docker-compose.elk.yml` publish `5044`/`9600`; anyone reaching the host can inject
arbitrary log documents (log forgery). **Fix:** don't publish; add token/mTLS on the HTTP input.

### LOW — no `no-new-privileges`/`read_only`/`cap_drop` on any service; nginx has no `limit_req` rate
limiting; hardcoded `8.8.8.8` resolver; CSP `style-src 'unsafe-inline'`; obsolete `version:` keys.

### ✓ Positives: **no fail-open `:-` secret defaults and no hardcoded credentials in any compose file**
(every secret uses fail-closed `${VAR:?}`); prod uses Docker file-secrets; main `Dockerfile` is multi-stage,
non-root, pinned, HEALTHCHECK'd; strong nginx TLS/headers in `default.conf`.

## §F — Infra deploy/secrets/observability (shell + yaml under infrastructure/)

### F1 (HIGH) — `deploy.sh` still builds, pushes and deploys `:latest`, undermining the immutable-tag control
`infrastructure/scripts/deploy.sh:114-130`. `cmd_build` pushes `${ECR_REPO}:latest` + `ecs update-service
--force-new-deployment` (out-of-band from CDK), while `cmd_infra:87-94` calls `cdk deploy` **without**
`--context imageTag`, so `backend-stack.ts` (which now `throw`s on unset/`latest`) makes `cmd_full` fail.
Net: the working deploy path re-introduces mutable-`latest` rollouts (no deterministic rollback target),
defeating remediation row 194. **Fix:** `TAG=$(git rev-parse --short HEAD)`, pass `--context imageTag=$TAG`,
push only the SHA tag, let CDK roll the service.

### F2 (MED) — Secrets created with `PLACEHOLDER_CHANGE_ME` bodies + hardcoded `postgres` username
`infrastructure/secrets/secrets-rotation.yaml:82-90,148,162-167,181`. CFN writes these as AWSCURRENT v1.
**Fix:** use `GenerateSecretString` for the DB password; source username from SSM.

### F3 (MED) — Fail-open `:-` on Falco alert-channel credentials
`falco.docker-compose.yml:50,60-62` — `SMTP_PASSWORD=${SMTP_PASSWORD:-}` etc.; unset env silently drops
critical security alerts. **Fix:** remove `:-` so a missing alert channel fails at startup.

### F4 (MED) — Prometheus scrapes every target over plaintext HTTP, no auth; Falco webserver/HTTP output plaintext
`infrastructure/monitoring/prometheus.yml:27-68`; `falco.yaml:53-55,86-90`. **Fix:** restrict the monitoring
network; add bearer/mTLS + `scheme: https`.

### F5 (MED) — Falco "PII Data Exfiltration" rule has an operator-precedence bug
`complyeasy_rules.yaml:289-298` — missing parentheses around the `or` buffer-match disjunction makes 3 of 4
branches fire on **any** event (incl. inbound) and miss real outbound exfil. **Fix:** parenthesize the
disjunction.

### F6 (MED) — DB-migration scripts pass passwords on argv + world-readable `.env` backups
`server/scripts/migrate-to-aws-rds.sh` (multiple lines) and `update-database-url.sh` pass the master
password inside the `psql`/`pg_dump` connection-string argv (visible via `ps`/`/proc`) and `cp` the `.env`
(with plaintext DB password) to a backup without `chmod 600`. **Fix:** use `PGPASSWORD`/`~/.pgpass`;
`chmod 600` the backup.

### LOW — binary downloads (circom/OPA) without checksum verification before `sudo mv`; `console.log` in
rotation Lambda (acceptable in a bare Lambda); racy `curl|grep` health checks; `openpolicyagent/opa:latest`.

### ✓ Positives: deploy/setup shell uses `set -euo pipefail`, **no hardcoded secrets, no `curl|bash`**;
secrets injected via ECS `secrets:` not `environment:`; the rotation Lambda is a **real, complete 4-step
implementation** (not a stub) and was hardened to refuse default DB identities; **all 7 previously-claimed
infra CDK fixes are genuinely present** in `infrastructure/lib/*.ts` (immutable tag in CDK, ElastiCache
TLS+at-rest+AUTH, uploads-CORS, ALB HTTPS, log retention, rotation, S3 encryption) — the only caveat is
F1 (deploy.sh not updated to match the CDK control).
